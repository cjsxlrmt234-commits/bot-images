# 배틀로얄 카카오톡 챗봇 - 스킬 서버

카카오 i 오픈빌더용 배틀로얄 텍스트 서바이벌 게임 스킬(webhook) 서버입니다.
턴/생존자 수/HP/장비/자기장 등 게임 상태와 주사위(랜덤) 판정은 전부 이 서버 코드가
처리하고, 오픈빌더는 사용자의 입력을 받아 이 서버로 전달 → 응답을 그대로 카카오톡에
보여주는 역할만 합니다.

## 게임 규칙 요약 (v3)

### 명령어
- `/전투` : 새 전투 시작 (진행 중이던 전투가 있어도 새로 시작됨)
- `/프로필` : 보유 현금/금괴/비밀열쇠/장비 강화 단계 확인 (전투 중에도 가능)
- `/강화` : 장비 강화 메뉴 (전투 중에는 사용 불가 — "강화 시도" 버튼으로 실행)

### 데이터 구조: 계정(프로필) vs 전투
- **프로필**(계정 단위, 영구 보존): 현금, 금괴, 비밀열쇠, 장비 강화 단계.
  전투를 몇 번을 다시 해도 초기화되지 않고 계속 쌓입니다.
- **전투**(판 단위): 턴 수, 생존자 수, HP. `/전투`(= "다시하기")를 누르면
  이 부분만 새로 초기화됩니다.

### 전투 규칙
- 정확히 **10턴** 이내로 종료. 매 턴 **반드시 2개**의 선택지만 제시:
  [파밍/교전 시도] / [도망 및 재정비]
- **파밍/교전** (하이 리스크): 보급 0.1% / 금괴 1.9% / 비밀열쇠 3% / 현금 5%
  (5,000~10,000원) / 1~3킬 10%(현금 1,000원×킬수) / 1킬 20%(현금 1,000원) /
  공격성공 30%(피해×10원 획득) / 피해 30%(HP 20~40)
- **도망** (로우 리스크): 보급 0.05% / 금괴 0.95% / 비밀열쇠 1.5% / 현금 2.5%
  (5,000~10,000원) / 피해 25%(HP 10~20) / 회복 70%(HP 5~10)
- 보급 당첨 시 현금 10만원 / 금괴 10개 / 비밀열쇠 3개 중 **하나만** 각 33.3%
  확률로 지급 (메시지에 "[보급]"으로 표시)
- 생존자는 100명에서 시작해 매 턴 비율로 줄어들고, **10턴째에는 무조건 1명
  (자신)만 남도록 강제**됩니다. 즉 10턴을 버티면 항상 "치킨 획득"으로 끝나고,
  중간에 생존자가 1명이 되면(교전으로 다 처치한 경우) 10턴이 안 됐어도 그
  즉시 치킨 획득으로 종료됩니다 — 혼자 남았는데 계속 싸우는 일은 없습니다.
- HP 0 이하 → 즉시 사망. 전투가 끝나면(승리/사망 모두) "이번 전투로 얼마를
  벌었는지"를 `현금: 41,485원 (+5,200원)` 형태로 프로필 누적값과 함께 보여줍니다.

### 강화 (계정 단위, 전투 밖에서만)
- `+0~+20`, 비용은 **현금만** 사용 (비밀열쇠는 강화에 쓰이지 않습니다)
- 단계가 오를수록 성공률은 낮아지고 파괴 확률이 붙으며, 실패(파괴) 시 +0으로
  초기화됩니다. 단계별 확률/비용 표는 `game.js`의 `ENHANCE_TABLE`에 있습니다.
- 전투 중에 `/강화`나 "강화 시도"를 입력하면 "전투 중에는 강화할 수 없습니다"
  라는 안내만 나오고 실제 강화는 진행되지 않습니다.

### 기타 수정
- 킬로그의 부위-처치 묘사가 항상 말이 되게 고쳤습니다 (예: "헤드샷으로"는
  머리를 맞혔을 때만 나오고, 다리/가슴에는 붙지 않습니다).

## 상황별 이미지 (simpleImage)
매 턴 결과(파밍/교전/도망/연마 등)에 맞는 이미지를 카카오 `simpleImage` 출력으로
텍스트와 함께 보여줍니다. `images/` 폴더에 미리 만들어둔 PNG 14장이 들어있고,
`server.js`가 `/images` 경로로 정적 제공합니다. 이미지 주소는 서버가 실제
배포된 주소(요청 host)를 기준으로 자동 생성되므로, ngrok이든 Render든 어디에
배포하든 코드 수정 없이 그대로 동작합니다.

새 이미지로 바꾸거나 더 추가하고 싶으면:
- 같은 파일명으로 `images/*.png`를 교체하면 바로 반영됩니다 (예: 직접 그린 일러스트로 교체)
- 지금 있는 것과 같은 스타일(이모지+색배경)로 새로 만들고 싶으면
  `python3 scripts/generate_images.py`를 열어서 `ICONS` 목록을 수정 후 재실행
- 새 상황(category)을 추가하려면 `game.js`에서 해당 분기의 반환값에
  `category: '이름'`을 넣고, `server.js`의 `CATEGORY_IMAGE`에 파일명을 매핑

## 파일 구성
- `server.js` : Express 웹훅 서버, `/skill` 엔드포인트 + `/images` 정적 제공
- `game.js` : 게임 로직 (프로필/전투 상태 관리, 명령어 라우팅, 파밍/교전/도망/강화 판정)
- `kakao.js` : 오픈빌더 스킬 요청/응답 JSON 포맷 헬퍼 (simpleImage + simpleText)
- `db.js` : MongoDB에 유저별 `{ profile, battle }`을 저장/조회
- `images/` : 상황별 삽화 PNG 14장
- `scripts/generate_images.py` : 위 이미지들을 생성한 스크립트 (재실행/커스터마이즈용)

## 0. MongoDB 준비하기 (게임 상태 저장용)
서버가 재시작돼도 진행 중인 게임이 사라지지 않도록 MongoDB에 저장합니다.
무료로 쓸 수 있는 MongoDB Atlas 기준 안내입니다.

1. mongodb.com/cloud/atlas 가입 → "Build a Database" → **M0 (Free)** 선택 →
   클러스터 이름은 아무거나 → "Create"
2. "Database Access"에서 사용자 추가 (아이디/비밀번호 설정, 나중에 연결
   문자열에 그대로 들어갑니다)
3. "Network Access"에서 "Add IP Address" → **"Allow Access from Anywhere"**
   (0.0.0.0/0) 선택 → Confirm
   (Render 같은 PaaS는 고정 IP가 아니라서 이렇게 열어둬야 접속이 됩니다)
4. 클러스터의 "Connect" 버튼 → "Drivers" → Node.js 선택 → 연결 문자열 복사
   (`mongodb+srv://사용자명:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`)
   `<password>` 부분을 2번에서 만든 실제 비밀번호로 바꿔주세요.
5. Render 대시보드 → 서비스 선택 → 왼쪽 메뉴 "Environment" →
   "Add Environment Variable" 클릭
   - Key: `MONGODB_URI`
   - Value: 4번에서 복사한 연결 문자열
   → Save (저장하면 자동으로 재배포됩니다)

로컬에서 테스트할 때는 같은 값을 환경변수로 export 하거나, `.env` 파일에
`MONGODB_URI=...`로 넣고 실행 전에 `export $(cat .env | xargs)` 해주세요.

`MONGODB_URI`가 없으면 서버는 죽지 않고, `/skill` 요청마다 "오류가
발생했습니다..." 라는 안내만 돌려줍니다. 잘 안 될 땐 Render "Logs" 탭에서
`MONGODB_URI 환경변수가 설정되지 않았습니다` 같은 메시지가 있는지 먼저
확인하세요.

## 1. 로컬에서 실행하기
```bash
npm install
npm start
```
`http://localhost:3000/skill` 로 서버가 뜹니다. (헬스체크: `GET /`)

간단히 테스트해보려면:
```bash
curl -X POST localhost:3000/skill \
  -H 'Content-Type: application/json' \
  -d '{"userRequest":{"user":{"id":"test"},"utterance":"/전투"}}'
```

## 2. 오픈빌더에 연결하기
오픈빌더는 인터넷에서 접근 가능한 https URL만 등록할 수 있어서, 로컬 서버를
그대로 쓸 수는 없습니다. 아래 둘 중 하나로 외부에 노출해야 합니다.

### 방법 A. ngrok으로 임시 테스트
```bash
ngrok http 3000
```
발급받은 `https://xxxx.ngrok-free.app` 주소 뒤에 `/skill`을 붙여서
(`https://xxxx.ngrok-free.app/skill`) 오픈빌더에 등록합니다.
※ ngrok 무료 플랜은 재시작할 때마다 주소가 바뀌니 계속 테스트할 땐 아래 방법 B를 추천합니다.

### 방법 B. 무료 호스팅에 배포 (Render, Railway, Fly.io 등)
이 폴더를 GitHub 저장소에 올리고, Render 같은 곳에서:
- Build Command: `npm install`
- Start Command: `npm start`
로 배포하면 `https://프로젝트명.onrender.com/skill` 같은 고정 주소가 생깁니다.

### 오픈빌더 설정
1. i.kakao.com 접속 → 봇 선택 → 좌측 메뉴 "스킬"
2. "스킬 추가" → URL에 위에서 얻은 `.../skill` 주소 입력, 저장
3. "시나리오" 탭에서 웰컴 블록(또는 새 블록)의 "봇 응답" 설정에서
   "스킬로 응답하기"를 선택하고 방금 등록한 스킬을 지정
4. 같은 방식으로 "폴백 블록"(정해진 답이 없을 때 실행되는 블록)도 이 스킬로 연결해두면
   사용자가 아무 말이나 입력해도 게임이 계속 진행됩니다
   (이 서버는 quickReply로 준 선택지 라벨과 "시작/다시하기"만 이해하고,
   나머지 입력은 "선택지 중에서 골라달라"고 재안내합니다)
5. 우측 상단 "봇테스트"로 대화해보면서 확인
6. 문제없으면 "배포" 탭에서 실제 채널로 배포

## 3. 알아두면 좋은 점 (프로토타입 한계)
- 게임 상태는 MongoDB에 저장되므로 서버가 재시작돼도 유지됩니다. 다만 MongoDB
  연결이 느리거나 실패하면(예: 잘못된 URI, 네트워크 문제) 그 요청은 실패 응답을
  돌려줍니다 (최대 3초 안에 실패하도록 타임아웃을 짧게 잡아뒀습니다).
- 지금은 킬로그 문구를 정해진 텍스트 풀에서 뽑아 쓰는데(`game.js`의
  `WEAPON_NAMES`, `BODY_PARTS`, `KILL_METHODS` 등), 좀 더 다양한 "느낌"을 주고 싶다면
  이 텍스트를 만드는 부분만 LLM 호출로 바꿔도 됩니다. 단, 승패/데미지/생존자 수 같은
  실제 판정은 지금처럼 서버 코드(주사위)가 계속 담당하는 게 안전합니다. (LLM이 판정까지
  하면 매번 결과가 달라져서 게임 밸런스가 깨지기 쉬워요.)
- 카카오 스킬 서버는 응답을 보통 5초 이내에 줘야 합니다. 지금 로직은 전부 동기 계산이라
  문제없지만, 나중에 LLM 호출을 추가하면 타임아웃에 걸리지 않게 주의하세요.
